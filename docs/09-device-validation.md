# 09 — Установка на iPhone и проверка входа

Инструкция для владельца: как собрать приложение, поставить его на свой iPhone и пройти реальный вход
через свой сервер. Предварительных знаний о структуре проекта не требуется.

Что проверяется на этом этапе: заставка, вход, ошибки (неверный пароль, нет соединения), обязательная
смена временного пароля, экран «Чаты» (пустой), «Настройки», выход и повторный вход, скрытая диагностика.
Сообщений, групп, медиа и звонков в этой сборке нет — и это намеренно.

---

## Часть 1. Сервер

Приложению нужен работающий сервер. Выберите **один** вариант.

### Вариант A (рекомендуется): VPS с доменом

Подходит, если есть Linux-сервер с Docker и домен, A-записи которого указывают на этот сервер.

1. На сервере:
   ```bash
   git clone https://github.com/Mnekrash/XMPP.git /opt/messenger
   cd /opt/messenger
   git checkout claude/private-ios-xmpp-messenger-kx8975
   cp deploy/.env.example deploy/.env
   ```
2. В `deploy/.env` указать:
   - `XMPP_DOMAIN=chat.ваш-домен.ru`;
   - `UPLOAD_DOMAIN=upload.ваш-домен.ru` (DNS-запись нужна для обоих);
   - `TLS_MODE=ваш@email` (тогда Caddy выпустит настоящий сертификат Let's Encrypt);
   - все пароли и секреты: каждый сгенерировать командой `openssl rand -hex 32`.
3. Запуск:
   ```bash
   scripts/render-config.sh
   docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d --build --wait
   scripts/sync-certs.sh
   scripts/admin.sh init
   ```
4. Открыть порты 80, 443, 5222 и 5223. Остальные порты должны быть закрыты.

В `Local.xcconfig` (Часть 3, шаг 6) значения будут такими: `XMPP_DOMAIN = chat.ваш-домен.ru` и `XMPP_HOST = chat.ваш-домен.ru`.

### Вариант B: сервер на вашем Mac, iPhone в той же Wi-Fi сети

Подходит для быстрой проверки без VPS. Нужен Docker Desktop на Mac.

1. На Mac:
   ```bash
   cd ~/Developer/XMPP          # папка из Части 3, шаг 2
   cp deploy/.env.example deploy/.env
   ```
2. В `deploy/.env` указать:
   - `XMPP_DOMAIN=chat.messenger.test`;
   - `UPLOAD_DOMAIN=upload.messenger.test`;
   - `TLS_MODE=internal`;
   - секреты: `openssl rand -hex 32`.
3. Запуск:
   ```bash
   scripts/render-config.sh
   docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d --build --wait
   scripts/sync-certs.sh
   scripts/admin.sh init
   ```
4. Узнать Wi-Fi IP Mac: `ipconfig getifaddr en0` (например, `192.168.1.20`).
5. Корневой сертификат локального CA нужно установить на iPhone, иначе защищённое соединение не установится:
   ```bash
   docker compose -f deploy/docker-compose.yml --env-file deploy/.env cp caddy:/data/caddy/pki/authorities/local/root.crt ~/Desktop/messenger-dev-ca.crt
   ```
   - Отправить файл на iPhone через AirDrop.
   - На iPhone: Настройки → «Профиль загружен» → Установить.
   - Затем: Настройки → Основные → Об этом устройстве → Доверие сертификатам → включить переключатель у сертификата Caddy.
6. Если в macOS включён брандмауэр, разрешить входящие подключения для Docker.

В `Local.xcconfig` значения будут такими: `XMPP_DOMAIN = chat.messenger.test` и `XMPP_HOST = 192.168.1.20` (IP вашего Mac).
Сертификат проверяется по домену аккаунта, а не по адресу подключения, поэтому вход по IP работает.

При первом входе iOS спросит разрешение на доступ к **локальной сети** — нажмите «Разрешить».
Если первая попытка входа завершилась ошибкой «Нет соединения» в момент появления этого вопроса, просто повторите вход.

## Часть 2. Тестовые аккаунты test1 и test2

Аккаунты создаёт только администратор, на сервере (в варианте B — на Mac, в папке проекта):

```bash
scripts/admin.sh create test1 "Тест Один"
scripts/admin.sh create test2 "Тест Два"
```

- Каждая команда один раз печатает **временный пароль**. Скрипт его нигде не сохраняет. Перепишите пароль для проверки и никуда не коммитьте.
- Аккаунт создаётся с пометкой «нужно сменить пароль». После первого входа приложение откроет экран смены пароля.
- Новый временный пароль: `scripts/admin.sh reset-password test1`. Пометка о смене пароля при этом ставится снова.
- Список аккаунтов: `scripts/admin.sh list`.

### Как работает обязательная смена пароля

Это **политика на стороне клиента**, а не ограничение сервера:

- `admin.sh` записывает в приватное хранилище аккаунта (XEP-0049) флаг `<account xmlns='urn:x-messenger:account' must-change-password='true'/>`.
- После входа приложение читает этот флаг и не пускает дальше, пока пароль не сменён.
- После смены пароля (XEP-0077) приложение снимает флаг.
- Сам ejabberd временный пароль **не блокирует**. Сторонний XMPP-клиент сможет войти с ним и работать.

Как позже перейти на серверную политику без изменения UI:

- UI получает признак только из `AccountInfo.mustChangePassword`, который возвращает `AuthService`.
- Серверная проверка (например, модуль ejabberd или внешняя аутентификация, которые до смены пароля разрешают только запрос смены) меняет лишь источник этого признака в `XMPPTransport` / `Authentication`.
- Экраны при этом не меняются.

## Часть 3. Установка на iPhone (12 шагов)

**Что понадобится:**

- Mac с **Xcode 16 или новее** (App Store);
- Apple ID, входящий в платную команду Apple Developer Program;
- iPhone с iOS 18 или новее и кабель;
- [Homebrew](https://brew.sh).

1. **Xcode и аккаунт.**
   - Установить Xcode и один раз запустить его, согласиться с лицензией.
   - Xcode → Settings → Accounts → «+» → Apple ID → войти.
   - Убедиться, что в списке Team видна ваша команда (не «Personal Team»).

2. **Скачать проект.** В Терминале:
   ```bash
   mkdir -p ~/Developer && cd ~/Developer
   git clone https://github.com/Mnekrash/XMPP.git
   cd XMPP
   git checkout claude/private-ios-xmpp-messenger-kx8975
   ```
   Без git: на GitHub выбрать ветку `claude/private-ios-xmpp-messenger-kx8975` → Code → Download ZIP и распаковать в `~/Developer/XMPP`.

3. **Установить XcodeGen:**
   ```bash
   brew install xcodegen
   ```

4. **Узнать Team ID.**
   - developer.apple.com → Account → Membership details → Team ID (10 символов, например `AB12CD34EF`).

5. **Выбрать Bundle ID.**
   - Нужен префикс, который принадлежит вам и уникален в Apple, например `com.maksim.messenger`.
   - Сборка для разработки получит идентификаторы:
     - `com.maksim.messenger.dev` — приложение;
     - `com.maksim.messenger.dev.notification-service` — расширение уведомлений (NSE).
   - Регистрировать их вручную не нужно: Xcode сделает это сам (автоматическая подпись).

6. **Создать личный конфиг.** Файл не попадает в git:
   ```bash
   cd ~/Developer/XMPP/ios
   cp Config/Local.xcconfig.example Config/Local.xcconfig
   open -e Config/Local.xcconfig
   ```
   Заполнить четыре строки:
   ```
   DEVELOPMENT_TEAM = AB12CD34EF
   APP_BUNDLE_ID_PREFIX = com.maksim.messenger
   XMPP_DOMAIN = chat.ваш-домен.ru      // вариант B: chat.messenger.test
   XMPP_HOST = chat.ваш-домен.ru        // вариант B: Wi-Fi IP вашего Mac
   ```

7. **Сгенерировать проект Xcode.** Из папки `ios`:
   ```bash
   xcodegen generate
   ```
   - Появится файл `~/Developer/XMPP/ios/Messenger.xcodeproj`.
   - После каждого `git pull` и после изменения `Local.xcconfig` команду нужно повторить.

8. **Открыть проект:**
   ```bash
   open Messenger.xcodeproj
   ```
   - Открывать именно `ios/Messenger.xcodeproj`. Не `Package.swift` и не папку `Packages`.
   - При первом открытии Xcode скачает зависимости (Martin и др.). Дождитесь окончания «Resolving Package Graph» внизу окна.

9. **Проверить подпись (Team) и возможности.**
   - В левой панели выбрать синий значок проекта **Messenger**.
   - Открыть таргет **Messenger** → вкладка **Signing & Capabilities**:
     - включено «Automatically manage signing»;
     - Team = ваша команда (подставляется из `Local.xcconfig`);
     - Bundle Identifier = `<префикс>.dev`;
     - в списке возможностей есть **Push Notifications** (её задаёт файл entitlements, добавлять вручную не нужно).
   - Открыть таргет **NotificationService** (это NSE):
     - тот же Team;
     - Bundle Identifier = `<префикс>.dev.notification-service`.
   - Если Team пустой, выбрать команду в выпадающем списке и повторить шаги 6–7.
   - Красных ошибок подписи быть не должно.

10. **Подключить iPhone.**
    - Подключить кабелем, разблокировать, нажать «Доверять этому компьютеру».
    - Включить режим разработчика: на iPhone Настройки → Конфиденциальность и безопасность → **Режим разработчика** → вкл.
    - iPhone перезагрузится; после перезагрузки подтвердите включение.
    - Пункт появляется после первого подключения к Xcode.

11. **Выбрать схему и устройство.**
    - В верхней панели Xcode выбрать схему **Messenger**.
    - Справа от неё выбрать свой iPhone (не симулятор).
    - Схема собирает конфигурацию Development: приложение «Messenger Dev» вместе со встроенным NSE.

12. **Собрать и установить:** Product → Run (⌘R).
    - Первая сборка занимает несколько минут.
    - Если macOS спросит доступ к связке ключей для подписи, нажмите «Всегда разрешать».
    - Если iPhone покажет «Ненадёжный разработчик», откройте Настройки → Основные → VPN и управление устройством → ваш сертификат разработчика → Доверять.
    - Приложение появится на экране «Домой» под именем **Messenger Dev**.

## Часть 4. Пользовательский сценарий (10 шагов)

1. Администратор выполняет `scripts/admin.sh create test1 "Тест Один"` и получает временный пароль.
2. Администратор передаёт пользователю логин `test1` и временный пароль любым надёжным способом.
3. Пользователь открывает «Messenger Dev»: заставка с логотипом, затем экран входа.
4. Вводит логин `test1`, временный пароль и нажимает «Войти». На кнопке крутится индикатор загрузки.
5. Приложение открывает экран «Придумайте пароль»: дальше без смены пароля пройти нельзя.
6. Пользователь вводит новый пароль (минимум 10 символов; лучше 12 и больше: буквы, цифры и знаки) и повторяет его. Слишком простой пароль сервер отклонит, и приложение покажет понятную ошибку.
7. Пароль меняется на сервере, новый пароль сохраняется в Keychain устройства, пометка о смене снимается.
8. Открывается экран «Чаты»:
   - в заголовке — статус соединения;
   - в центре — «Нет чатов»;
   - внизу — вкладки «Чаты» и «Настройки».
9. Пользователь закрывает и снова открывает приложение. Сохранённая сессия восстанавливается, и сразу открываются «Чаты», без экрана входа.
10. «Настройки» → «Выйти» → подтверждение. Открывается экран входа. Вход с новым паролем возвращает в «Чаты»; старый временный пароль больше не работает.

## Часть 5. Что проверить (чек-лист)

| # | Проверка | Ожидается |
|---|----------|-----------|
| 1 | Внешний вид: иконка, заставка, экран входа | без полей «сервер», «домен», «порт» и т.п.; только логин и пароль |
| 2 | Вход с неверным паролем | «Неверный логин или пароль», поле пароля доступно для повтора |
| 3 | Вход в авиарежиме | ошибка об отсутствии соединения, без технических терминов |
| 4 | Вход с временным паролем | экран смены пароля |
| 5 | Слабый новый пароль (например, `1111111111`) | понятная ошибка, пароль не изменён |
| 6 | Нормальный новый пароль | экран «Чаты», «Нет чатов» |
| 7 | Статус соединения: включить авиарежим на экране «Чаты», затем выключить | «Ожидание сети…», затем «Подключение…», затем обычный заголовок |
| 8 | Перезапуск приложения | сразу «Чаты» |
| 9 | «Настройки» | имя «Тест Один», @test1, версия |
| 10 | Выход и повторный вход новым паролем | работает; старый пароль — «Неверный логин или пароль» |
| 11 | Тёмная тема (Пункт управления) | все экраны читаемы |
| 12 | Диагностика: «Настройки» → 5 раз быстро нажать на строку «Версия» | connected, authenticated, domain, Stream Management, push token, OMEMO device ID, версия |

В диагностике push token покажет «not registered (S2)», а OMEMO device ID — «not created (Phase 5)».
Это честные значения: регистрация push и OMEMO в эту сборку ещё не входят.

Отключённый аккаунт: `scripts/admin.sh disable test2 "проверка"`, затем вход как test2 → сообщение, что аккаунт отключён.
Включить обратно: `scripts/admin.sh enable test2`.

## Часть 6. Если что-то не так

| Симптом | Причина и решение |
|---------|-------------------|
| `xcodegen: command not found` | шаг 3 |
| «No account for team…» / «Signing requires a development team» | шаги 1, 6, 7: Apple ID в Xcode, Team ID в `Local.xcconfig`, повторить `xcodegen generate` |
| «Failed to register bundle identifier» | префикс занят: выбрать другой `APP_BUNDLE_ID_PREFIX`, шаги 6–7 |
| iPhone не виден в списке устройств | разблокировать, «Доверять», включить режим разработчика (шаг 10) |
| «Нет соединения», хотя интернет есть | неверный `XMPP_HOST`; порт 5223 закрыт; вариант B: iPhone не в той же Wi-Fi сети или не разрешён доступ к локальной сети |
| Ошибка защищённого соединения | вариант A: сертификат ещё не выпущен или не скопирован (`scripts/sync-certs.sh`); вариант B: не установлен или не включён в «Доверии сертификатам» корневой сертификат |
| «Неверный логин или пароль» с только что выданным паролем | `XMPP_DOMAIN` в `Local.xcconfig` не совпадает с `XMPP_DOMAIN` в `deploy/.env` |
